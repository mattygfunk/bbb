Poker Guide: Bankroll + Volume Framework

This is your operating system for poker. It is designed for Big Bluff Bay’s schedule cadence, where players can easily over-register and under-review. The goal is not “play more” — the goal is play better, consistently.

Use this with Poker Schedule, Poker FAQ, and Poker Rules.

1) Bankroll structure: define your envelope before the week starts

Create a weekly envelope, not a session-by-session guess. A clean split prevents emotional overreach.

  • Core allocation (60–70%): your highest-confidence, planned events.
  • Optional allocation (20–30%): conditional entries only if focus remains high.
  • Protection buffer (10%): not for chasing; reserved for volatility control.

Hard rule: no borrowing from next week’s bankroll to recover this week’s losses.

2) Volume design: anchor first, then earn extras

Start with anchors (planned events). Optional entries are earned by decision quality, not mood.

  • Pick anchor events from Poker Schedule.
  • Set a maximum event count for the week.
  • Gate optional entries behind a checklist:
    • Energy ≥ 7/10
    • Focus intact
    • No tilt signal in last 45 minutes

If checklist fails, skip. Protecting quality is a win.

3) Risk controls that prevent silent bankroll bleed

  • Session cap: set before the first reg.
  • Stop-loss trigger: fixed threshold where no new events are allowed.
  • Tilt lock: after two emotional decisions, 10-minute hard break.
  • Late-night cutoff: no optional add-ons after your quality window closes.

These controls are boring — and that’s exactly why they work.

4) Weekly review loop (the compounder)

Without review, volume just repeats mistakes faster. Use this compact loop:

  1. Tag 10 hands across the week (not only bust-out hands).
  2. Label each as: technical leak, emotional leak, or variance-only.
  3. Choose one correction for next week only.
  4. Track if that correction actually improved outcomes.

For structure, pair this with Session Review Scorecard and Hand History Review System.

5) Example weekly template (practical)

  • Sunday: Main Event (anchor)
  • 2–4 nightly events: only if quality metrics are met
  • 1 review block: 45–60 minutes post-week

If you also play local live sessions, reduce total online volume slightly to maintain decision quality.

Common failure patterns this framework solves

  • Impulsive registrations after bad beats
  • Event overload without focus capacity
  • No objective feedback loop
  • Confusing activity with improvement
