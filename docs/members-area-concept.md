# Big Bluff Bay members area — concept

## Recommendation

Keep event discovery public and account-free for now. Test whether players return for saved events, city filters and calendar downloads before adding registration. If repeat use is strong, introduce a free, optional account focused on personalising a public event calendar.

The homepage should infer relevance from the visitor's selected city or state filter. Do not request GPS access. Until a visitor chooses a location, feature the next checked event anywhere in Australia.

## Useful member features

1. **Home city or state** — make the event spotlight and default search relevant on return.
2. **Synced saved events** — keep a shortlist available across devices, with the existing calendar export.
3. **Saved searches** — remember event type, date window, game format and entry range.
4. **Schedule alerts** — opt-in email when a followed organiser adds an event or a checked schedule changes. Show the source and last-checked date, and include clear unsubscribe controls.
5. **Personal reminders** — add event dates to a calendar or send a reminder chosen by the member.
6. **Account controls** — let members export or delete their saved preferences and close their account.

## A careful rollout

- **Now:** Keep the local saved-event feature and shareable search links. They work without an account and show whether people want these features.
- **If members ask for sync:** Add a free account with only an email address, saved event IDs, chosen home location and explicit alert preferences.
- **After measuring demand:** Add schedule-change alerts and saved-search notifications with double opt-in, frequency controls and unsubscribe links.

## Keep out of scope

A member area should make live-event discovery easier. Avoid deposits, bankroll tracking, staking, online poker play, public player profiles, chat and leaderboards. Those features add financial, privacy, moderation and regulatory complexity without improving the core event finder.

## Data and trust rules

Event listings remain public, source-linked and independently checkable. A member preference must never silently change event facts. Collect only what powers a requested feature; provide export and deletion controls before launch.
